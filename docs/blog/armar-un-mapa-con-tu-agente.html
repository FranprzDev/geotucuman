Cómo armar un mapa con tu agente usando GeoArg

Resumen: el agente no dibuja el mapa. Lo que hace es encontrar las capas correctas en el catálogo, mostrar sus campos y dejar listos los pedidos de datos. Con esas piezas, el mapa lo arma tu código. El flujo es search_layers → describe_layer → query_layer, con suggest_layers y geocode como apoyo.

Blog de GeoArg · Documentación del MCP

El flujo en pasos

  1. search_layers (o suggest_layers) encuentra capas candidatas por palabra clave o por objetivo.
  2. describe_layer muestra los campos reales y los servicios de la capa elegida. Es obligatorio antes de consultar.
  3. query_layer pide los features con bbox, filtros y paginación.
  4. geocode convierte un texto en coordenadas cuando necesitás centrar el mapa sin conocer el bbox.

suggest_layers ordena candidatas a partir de un objetivo en texto libre, de forma determinista y sin LLM. geocode usa la API Georef, sin key.

Conexión

Endpoint público Streamable HTTP de GeoArg:

https://geoarg-mcp.franprzdev.workers.dev/mcp

Configuración genérica para un cliente MCP:

{
  "mcpServers": {
    "geoarg": {
      "url": "https://geoarg-mcp.franprzdev.workers.dev/mcp"
    }
  }
}

El endpoint es de solo lectura y no requiere API key. Depende de Cloudflare Workers y de servicios oficiales de terceros, así que puede fallar o demorar. Más detalle en la documentación del MCP.

Ejemplo real: objetivo "agua"

Buscando en el catálogo las capas cuyo título o resumen menciona "agua", aparecen 142 capas en 12 jurisdicciones. El script elige 3 ejemplos por perfil de servicio y jurisdicción distinta, sin intervención manual:

CapaJurisdicciónServicios
Acequia, zanja, zanjónArgentina (nacional)WFS + WMS
Corriente de agua intermitenteBuenos AiresWFS + WMS
Batimetria Concepción del UruguayEntre RíosWMS

Con esos tres candidatos el paso siguiente es describe_layer sobre cada uno para ver los campos reales, y recién después query_layer. Las capas solo WMS quedan para el fondo del mapa; las que incluyen WFS o ArcGIS REST se pueden consultar.

Qué hace el agente y qué no

El agente sugiere capas, las describe y arma las consultas. No construye el mapa por vos: el render, los estilos y la composición final son de tu código o de tu SIG. GeoArg tampoco aloja los datos: consulta los servicios oficiales en vivo y cita la fuente.

Un caso aplicado completo está en Focos de calor vs agua en Tucumán, donde el MCP descubre las capas y luego el análisis consulta los servicios directamente.

Fuente de los datos

Todos los números de esta nota salen de data/catalog.json, generado el 2026-11-13 (campo generatedAt). Son entradas del catálogo, no capas verificadas en vivo una por una.
