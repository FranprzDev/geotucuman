WMS vs WFS: cuál usar para tu mapa

Resumen: WMS y WFS resuelven cosas distintas. WMS devuelve una imagen ya dibujada para poner en el mapa; WFS y ArcGIS REST devuelven features que se pueden filtrar, contar y analizar. En el catálogo de GeoArg hay 2920 capas ofrecidas como WFS + WMS, 716 solo WMS, 4 solo WFS y 9 solo ArcGIS REST.

Blog de GeoArg · Documentación del MCP

WMS: una imagen para mirar

WMS (Web Map Service) recibe un pedido con un bbox y un tamaño y devuelve un PNG. El cliente no recibe entidades ni atributos: recibe píxeles ya coloreados por el servidor. Sirve para mostrar una capa de fondo o temática, y no permite preguntar "¿cuántos polígonos hay acá?" ni "¿cuál es el nombre de esta feature?".

WFS y ArcGIS REST: datos consultables

WFS (Web Feature Service) devuelve features con su geometría y sus atributos en GML, GeoJSON o similar. ArcGIS REST cumple el mismo rol a través de la API de ArcGIS (FeatureServer). Con estos servicios se puede filtrar por atributo, pedir solo ciertos campos, contar registros y leer el valor de cada campo.

Qué dice el catálogo

La mayoría de las capas provinciales publica las dos variantes a la vez. Las capas de solo WMS suelen ser servicios que solo exponen visualización.

Qué puede consultar query_layer

query_layer aplica a capas WFS y ArcGIS REST. Para las capas solo WMS, query_layer no aplica: el servicio entrega imágenes, no features. Igual se pueden buscar y describir (search_layers y describe_layer) porque sus metadatos están en el catálogo.

Una regla práctica

Si solo necesitás ver la capa, usá WMS. Si necesitás saber algo de la capa (contar, filtrar, cruzar, leer atributos), usá WFS o ArcGIS REST. Cuando la capa ofrece las dos, WMS para el fondo y WFS para la consulta.

Validá cada capa antes de confiar en ella

Algunas capas fallan de forma intermitente, aunque su servicio esté declarado en el catálogo. Antes de consultar, corré describe_layer sobre la capa elegida: si responde, seguí con query_layer. Si falla, probá otra capa o reintentá más tarde. El monitoreo por capa está en salud de capas.

Fuente de los datos

Todos los números de esta nota salen de data/catalog.json, generado el 2026-11-13 (campo generatedAt). Son entradas del catálogo, no capas verificadas en vivo una por una.
