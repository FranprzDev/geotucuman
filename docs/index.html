GeoTucumán

MCP (Model Context Protocol) de descubrimiento y consulta de geodatos públicos, empezando por Tucumán, Argentina.

Ver catálogo de capas Repositorio en GitHub

Qué es

  • Es una capa de descubrimiento y consulta sobre servicios WFS oficiales y la API Georef.
  • Descubre y sugiere datasets públicos descargables según lo que necesités (con metadata: quién publica, de cuándo es el dato, cómo descargar). No arma el mapa ni el análisis por vos.
  • Corre local por stdio con tu cliente MCP (por ejemplo Claude Code).
  • No es un SIG completo, ni un visor, ni una copia de los datos: consulta en vivo y cita la fuente.
ToolQué hace
buscar_capasBusca capas por palabra clave en el catálogo embebido

Probá que funciona

1. Descubrir datasets por intención

El corazón de GeoTucumán: decir qué necesitás en palabras comunes y encontrar el dataset.

“quiero hacer un mapa sobre agua” → “cultivos de soja” → “radios censales” →

2. Geocodificar (Georef, en vivo)

Escribí una dirección y tocá Geocodificar.

3. Consultar capa (WFS del IGN, en vivo)

Elegí una capa y tocá Consultar en vivo.

Qué hay atrás

  • Servidor MCP por stdio con @modelcontextprotocol/sdk, escrito en TypeScript estricto y validación con zod.
  • Catálogo embebido generado desde los GetCapabilities en vivo (npm run catalog), con estado por fuente: live o snapshot preservado si el endpoint cae.
  • El bbox se consulta en EPSG:4326 y el servidor lo reproyecta al CRS nativo de cada capa; reproyección Gauss-Krüger/TM propia para EPSG:22183 y EPSG:5345 verificada contra proj4 con error < 0.001 m.

Quickstart:

npm install
npm run catalog
npm run smoke
npm run portal
npm run build && npm start

Config de cliente MCP (ej. Claude Code):

{ "mcpServers": { "geotucuman": { "command": "node", "args": ["/ruta/geotucuman/dist/server.js"] } } }
