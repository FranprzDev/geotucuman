Cinco herramientas

search_layers

Busca capas por tema o palabra clave en el catálogo embebido.

suggest_layers

Sugiere capas a partir de un objetivo en texto libre (determinista, sin LLM), con filtro opcional por tipo de servicio WFS/WMS.

describe_layer

Devuelve los campos reales de una capa. Obligatorio antes de consultarla.

query_layer

Trae features con filtros, paginación y bbox en EPSG:4326, reproyectado al CRS nativo de cada capa.

geocode

Convierte una dirección en coordenadas con la API Georef (gratis, sin key).

Cómo usarlo

De cero a tu agente en cuatro pasos

  1. Cloná e instalá
    git clone https://github.com/FranprzDev/geotucuman.git
cd geotucuman
npm install
  2. Compilá el servidor
    npm run build
    Genera dist/stdio.js y dist/http.js con xmcp.
  3. Conectalo a tu cliente MCP (ejemplo Claude Code):
    { "mcpServers": { "geomcp": { "command": "node", "args": ["/ruta/geotucuman/dist/stdio.js"] } } }
  4. Listo: las cinco herramientas quedan disponibles en tu agente.

Corre local por stdio. También compila un transporte HTTP (npm run start:http) pensado para hosting futuro: hoy no hay un servidor remoto público.

En una frase

Descubre la capa, dice quién la publica y de cuándo es, y la consulta en vivo en la fuente oficial. No dibuja mapas ni copia datos.

Cobertura y fuentes

De dónde salen los datos

El catálogo embebido descubre hoy 22 Planeamiento · 76 Catastro · 192 IGN · 253 RIDES = 543 capas, generado desde los GetCapabilities en vivo (si un endpoint cae, se conserva un snapshot).

IGN y la API Georef tienen cobertura nacional. Las fuentes provinciales integradas hoy son de Tucumán; sumar otra provincia es agregar su servicio WFS o WMS a la configuración.
