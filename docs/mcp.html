GeoArg: geodatos públicos de Argentina para tu agente

GeoArg es un servidor MCP (Model Context Protocol) para descubrir y consultar geodatos públicos de Argentina. Se puede usar local por stdio o contra el endpoint público Streamable HTTP. Es gratis, de código abierto (MIT), de solo lectura y no requiere API key.

English summary: GeoArg is a free, open-source (MIT) Model Context Protocol server for discovering and querying Argentine public geodata. It runs locally over stdio or through a public Streamable HTTP endpoint. It is read-only, needs no API key, and represents 22 provinces plus CABA, 23 of 24 Argentine jurisdictions; Formosa has no working source. Coverage depends on the specific catalog layers and their limitations. WMS layers are display imagery, while WFS and ArcGIS REST layers are queryable. Third-party services may change or fail.

Qué es y nombres anteriores

GeoArg indexa metadatos de servicios oficiales WFS, WMS y ArcGIS REST, más la API Georef, y permite que un agente busque capas, las describa y consulte datos en vivo. No es un SIG completo, ni un visor, ni una copia de los datos: enlaza la fuente y devuelve su atribución cuando está disponible.

El proyecto se llamó antes GeoTucumán y luego GeoMCP; el nombre visible pasó a GeoArg el 7/11/2026. El repositorio y la URL pública siguen en la ruta geotucuman.

Conexión

Endpoint público por Streamable HTTP

Endpoint MCP: https://geoarg-mcp.franprzdev.workers.dev/mcp

Es stateless, de solo lectura y no requiere API key. JSON genérico para un cliente MCP:

{
  "mcpServers": {
    "geoarg": {
      "url": "https://geoarg-mcp.franprzdev.workers.dev/mcp"
    }
  }
}

Claude Code, en una línea (comando documentado por Claude Code; no se verificó su ejecución en Claude desde este repositorio):

claude mcp add --transport http geoarg https://geoarg-mcp.franprzdev.workers.dev/mcp

El endpoint público depende de Cloudflare Workers y de servicios oficiales de terceros. Puede fallar, demorar o cambiar sin aviso, y GeoArg no controla su disponibilidad. Para uso local, el transporte por stdio no depende de ese Worker.

Instalación local por stdio

git clone https://github.com/franprzdev/geotucuman.git
cd geotucuman
npm install
npm run build

Configuración genérica por stdio, reemplazando la ruta por la de tu copia:

{
  "mcpServers": {
    "geoarg": {
      "command": "node",
      "args": ["/ruta/geotucuman/dist/stdio.js"]
    }
  }
}

Cinco herramientas principales

ToolQué hace y ejemplo real
search_layersBusca capas por palabra clave. Ejemplo: query: "aeropuerto" con province: "Tucumán" devuelve WFS_GEOSPLAN:aeropuerto.
suggest_layersSugiere capas desde un objetivo en texto libre, sin LLM. Ejemplo: goal: "quiero armar un mapa de riego y pozos".
describe_layerMuestra los campos reales de una capa y es obligatorio antes de consultar. Ejemplo: typeName: "dgct:PARCELASR1".
query_layerConsulta features de capas WFS o ArcGIS REST. El bbox va en EPSG:4326, se reproyecta al CRS nativo y acepta hasta 50 features con paginación. Ejemplo: typeName: "dgct:PARCELASR1" después de describe_layer.
geocodeConvierte texto libre en coordenadas con la API Georef, gratis y sin key. Ejemplo: text: "Yerba Buena, Tucumán".

Las capas WMS-only se pueden buscar y describir (metadatos vía GetCapabilities), pero query_layer no aplica: WMS entrega imágenes de mapa para visualización, mientras que WFS y ArcGIS REST entregan features consultables. Las 7 fuentes INTA integradas son WMS-only y usan una lista blanca de una capa por fuente.

Datos, atribución y cobertura

GeoArg no aloja ni redistribuye los datos: consulta servicios oficiales en vivo y devuelve la fuente. Cada organismo publica sus propios términos y licencias, que pueden variar por capa y deben revisarse antes de redistribuir o reutilizar. Que un servicio sea público no implica permiso de reutilización.

La cobertura alcanza 23 de las 24 jurisdicciones argentinas: están representadas 22 provincias + CABA, además del IGN nacional y la API Georef. Formosa no tiene una fuente operativa integrada: su IDE responde la portada pero cierra las conexiones WMS/WFS desde fuera de Argentina, según el diagnóstico del repositorio. Las Islas Malvinas no tienen una capa dedicada ni cobertura completa: solo pueden aparecer en capas específicas del catálogo, como las de Tierra del Fuego o del IGN nacional, con sus propios límites de cobertura.

La representación territorial y temática no es uniforme ni exhaustiva. En las fuentes INTA se indexa una sola capa por nodo; por ejemplo, Corrientes cubre el área cartografiada de Lomas Arenosas y no toda la provincia, Chubut aporta una capa regional Patagonia Sur sin recorte provincial, La Rioja es cobertura histórica 2006-2007 y La Pampa es productividad modelada 2001-2011 / series 2000-2013. La disponibilidad depende de terceros y puede cambiar sin aviso.
